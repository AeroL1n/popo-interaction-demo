# popo 交互动效 Demo

这是一个围绕 popo 核心体验搭建的高保真交互 Demo，重点呈现首页浏览、作品卡片、个人主页、消息通知浮层和发布入口等关键场景中的视觉状态与动效衔接。

它不是对单一页面的静态还原，而是一份可直接体验的设计说明：将尺寸、间距、层级、悬浮反馈、状态切换和页面跳转组织在同一个可运行环境中，让设计意图能够通过真实操作被理解和验证。

## 项目目标

- 用可运行的页面表达关键交互，减少仅依赖截图或文字说明产生的理解偏差。
- 将视觉规范与交互规则放在同一上下文中，便于对照、讨论和持续校准。
- 覆盖正常态、悬浮态、切换态、空状态与浮层等典型场景，补足静态视觉稿难以完整描述的体验细节。
- 为后续实现提供清晰、可复现的体验基线，同时保留必要的响应式与可访问性考虑。

## 体验范围

当前 Demo 主要包含：

- 首页作品流、分类标签、搜索入口与返回顶部等页面操作。
- 作品卡片的悬浮反馈、标签展示、详情浏览与个人主页状态。
- 顶部头像消息入口、通知浮层、消息与每周冒泡 Tab 切换。
- 评论、打气、徽章与系统通知等消息卡片样式及跳转反馈。
- 发个泡泡入口及相关视觉动效。
- 空状态、加载反馈和局部页面切换等辅助体验。

## 设计方法

Demo 以现有代码库规则和视觉稿为共同依据。可复用的产品行为优先与当前实现保持一致；视觉稿中的尺寸、字体、间距和层级则通过浏览器中的真实布局进行校准。对于静态稿无法完整表达的部分，使用克制的状态过渡补全交互，并保持运动节奏与页面整体语言一致。

这种方式让交互细节不再停留在抽象描述中：触发条件、元素关系、动效方向和状态结果都可以在页面中被直接观察，也方便在评审过程中快速定位差异。

## 运行与体验

- 在线演示：https://aerol1n.github.io/popo-interaction-demo/
- 建议环境：Chrome / Edge 最新版本
- 推荐分辨率：桌面端 1440px 及以上
- 本地入口：`demo/index.html`

本项目为静态交互演示。直接打开本地入口即可浏览；为获得更稳定的媒体加载与跨页面体验，也可以通过任意静态文件服务运行 `demo` 目录。

## 使用说明

建议按照首页浏览、卡片交互、个人主页、消息浮层和发布入口的顺序体验。部分按钮用于模拟产品内的页面跳转或状态变化，重点是验证交互路径、反馈节奏和视觉关系，不包含真实业务数据写入。

## 项目定位

这份 Demo 既是阶段性设计成果，也是设计与实现之间的沟通媒介。它把分散在视觉稿、标注和口头说明中的关键规则整理为统一、可操作的体验，使后续讨论能够围绕同一个基线展开，并让每一次调整都可以被快速验证。
